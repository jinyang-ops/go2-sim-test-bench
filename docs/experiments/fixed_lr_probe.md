# 固定学习率单轮对照

状态：入口和准入逻辑通过 CPU 测试，脚本通过 Bash 语法检查；尚未执行该对照的 GPU 训练或物理评估。不将计划写成修复结果。

依据：[已有诊断](../results/competition_transfer_regression.md)显示首轮更新后 actor 参数相对源权重已有约 6.67% 的 L2 变化，首轮检查点的短程评估也未达标。新优化器配置初始学习率 1e-3，高于源优化器保存时的 1e-5；源与各检查点的保存时学习率均为 1e-5，无法据此重建早期变化过程。学习率是候选解释，尚未证明为唯一根因。

## 控制条件

- 从原始已验证源模型重新加载完整 actor、critic、std，优化器与训练迭代重新开始。
- competition / flat、128 环境、seed=42，仅 1 个学习迭代，48 步/环境。一个学习迭代仍包含原配置的多个 epoch/mini-batch 更新，并非只调用一次 optimizer.step。
- 显式设置 `--qa-learning-rate 1e-5 --qa-lr-schedule fixed`，防止 adaptive 调度改变该学习率。
- 原奖励、命令、名义随机化配置及探索初始化保持；不重置或冻结 std，它仍可在 PPO 更新中学习。
- 额外保存 `qa_initial.pt`：加载源网络后、learn() 前的真正更新前检查点。角色、哈希和优化器起始学习率写入 qa_training.json。文件名避开上游按包含 model 的名字选择最新模型的逻辑。`model_0.pt` 仍是首轮更新后的原生保存文件，二者不可混淆。

优化器覆盖参数与 resume 互斥，避免恢复的优化器状态覆盖新配置。未指定这些参数时保留已有算法配置。每次实验使用独立运行名与输出目录。

## 一条命令执行训练与前后评估

在已激活的仿真 Python 环境、仓库根目录中：

```bash
bash scripts/probe_fixed_lr.sh \
  /absolute/path/to/original/model_1000.pt \
  reports/first_update_pair_TIMESTAMP/source
```

脚本先读取传入源评估的 summary.json 和 metadata.json：要求检查点 SHA256 与源文件一致，且 nominal / competition / heading、seed=0、单环境、1m/s、5s/1m 条件下达标。缺失、不一致或未达标时停止，不启动训练。该检查是已有记录的准入核对，不是在 CPU 环境独立复现结果。

通过准入后，脚本执行一轮训练，从训练日志读取实际保存路径，自动以相同 5s/1m 协议分别评估 qa_initial 和 model_1，并记录轨迹。输出默认保存在新的 reports/fixed1e5_seed42_时间_进程号 目录，可通过第三个参数指定全新目录。训练日志、源评估副本、两个模型评估的日志/CSV/元数据/汇总都保留；模型仍保存在上游实际 logs/qa_course_flat_lr_probe 中。

训练或脚本异常会停止后续操作。正式评估默认不设置成功率退出门槛，因此脚本正常完成只意味着执行完成，性能是否达标应读取两个 summary.json。

## 结果解释

|更新前检查|更新后一轮检查|下一步|
|---|---|---|
|达标|达标|支持该设置下的单回合能力保持，再做多种子验证与短预算训练；不据此宣称收敛|
|达标|未达标|低固定学习率仍不足以保留此项能力，继续检查采样轨迹与优势/价值更新|
|未达标|任意|先核对保存/加载、实际配置与重跑差异，不将结果归因于更新|

本次对照改变的是学习率与其调度策略，不证明二者各自的独立因果贡献。小样本与 GPU 重跑波动仍需考虑；只有后续统一协议的评估通过，才能恢复更长预算与坡面训练。
